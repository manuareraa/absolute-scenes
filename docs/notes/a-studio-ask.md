# Ask the pundit: viewer side (stream a)

Branch `stream/a-studio-ask`. The Worker route is in PR #70 (`stream/d-ask-route`).

## What viewers get
- **Ask bar** on the show and player surfaces. It has three suggestions; on a show moment the first is always "What should they have done?". Typing works with no mic.
- **Mic:** the Speech SDK loads only on the first tap, as its own chunk of about 400 KB. It gets a 10-minute token from `GET /api/voice-token`, so no key reaches the browser. With no token (501), the mic shows "voice is off" and typing still works.
- **Barge-in:** typing or speaking again stops the current answer. Esc closes the control room.
- **Control room:** a 300 px strip in broadcast-gallery style, with a tally light per agent.
  - It shows steps, tool runs (name, ms, summary) and verdicts. A rejected claim is struck through and shown with its round number, then the rewrite appears as "checked".
  - At the end it shows the counterfactual and an ON AIR tally.
- **Answer overlay** plays through the existing overlay player and `useOverlayAudio`, so numbers stay tappable. The ghost path is an ordinary `ghost_path` stroke. No renderer hooks were needed, so there is nothing in `a-requests.md`.
- **What-if lower third:** the proposal plus before → after metric chips, in green or red depending on whether the change helped.

## Feeds
- `?ask=fake` uses the rehearsal feed, `public/fixtures/ask/*.ndjson`, replayed at its recorded `t_ms` pace. It carries a REHEARSAL tag. It is regenerated by `web/scripts/ask_fixture.py`, and every line is tested against `ask-event.schema.json`.
- `?ask=live` uses only `POST /api/ask`.
- With no flag (auto), the app tries live and falls back to the rehearsal on 404, 501 or a network error. A 429 or 503 is shown to the viewer as "busy" or "off".
- A question the rehearsal has no answer for gets an honest refusal ("The live crew answers anything about the match."), never a made-up one. The player view with the `demo-001` fixture is an example.

## For stream c (crew): the request body
`POST /api/ask` sends the following (the Worker whitelists these fields and forwards them with `x-chalktalk-secret`):
```json
{ "question": "What should they have done?", "suggestion": "counterfactual",
  "match_id": "sim-7", "moment_id": "<overlay id on screen, optional>",
  "match_tc": 175400, "lang": "en-GB", "lens": "analyst", "side": "away" }
```
- `suggestion` is one of `counterfactual | space | chance | offside | press | key_player`, or absent for free text.
- The reply is NDJSON `AskEvent`s, ending with `done`.
- Not in `contracts/` yet. The coordinator may want an `ask-request.schema.json`.
